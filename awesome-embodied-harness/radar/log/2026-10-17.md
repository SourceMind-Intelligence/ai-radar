# Radar · 2026-10-17

## Signals

- **Personalization becomes a harness layer.** CarryOn wraps a frozen VLA in a planning loop that keeps persistent user-level and scene-level context, so "make me a sandwich" is decomposed according to the user's preferences, and pairs it with an execution loop for safety checks and recovery. PAM (CoRL 2026) learns a finite-state memory of each user's recurring routines, so a VLM can decide when to help unprompted. LIBERO-PeRM (NeurIPS 2026) gives the field a benchmark that separates task completion from preference satisfaction.
- **Verification moves inside the action chunk.** VeriVLA uses sample disagreement between two flow-VLA draws to detect critical states, then ranks candidate chunks with a JEPA latent world model. PAV checks whether executing a chunk prefix still allows the task to succeed, using the VLA's own representation space. "When to Ask for Help" turns the scheduling of a dual-system VLA's slow module into a value-of-intervention decision with a common measurement standard.
- **Instruction following has a deeper failure mode.** SIMPLER-IN shows that how-level instructions ("do it this way") do not help current VLAs and can lower success. This extends the what-level grounding gaps found earlier this month (Encoded but Not in Control, Rephrase Before You Act).

## Added

- **CarryOn** (harness): a dual-loop personalized and reliable assistance harness around a frozen VLA; code announced. [paper](https://arxiv.org/abs/2610.21453)
- **PAM** (harness): proactive assistance driven by a procedural routine memory (CoRL 2026). [paper](https://arxiv.org/abs/2610.21211)
- **VeriVLA** (verification): sample-disagreement triggers plus latent-world-model ranking of flow-VLA chunks. [paper](https://arxiv.org/abs/2610.21985)
- **PAV** (verification): policy-aligned predictive verification of action-chunk prefixes. [paper](https://arxiv.org/abs/2610.21434)
- **Value of Intervention (dual-system scheduling)** (policy): a decision-theoretic account of when to call the slow module. [paper](https://arxiv.org/abs/2610.21160)
- **REKI** (policy): a 2.4B public-data VLA with register-token memory. [paper](https://arxiv.org/abs/2610.22178)
- **VLRLA** (policy): in-context RL for deployment-time VLA adaptation with frozen weights. Promoted from the queue. [paper](https://arxiv.org/abs/2610.19517)
- **LIBERO-PeRM** (benchmark): personalized robotic manipulation (NeurIPS 2026). [paper](https://arxiv.org/abs/2610.22372)
- **SIMPLER-IN** (benchmark): how-level instruction following for VLAs. [paper](https://arxiv.org/abs/2610.21251)
- **HM3D-M3** (benchmark): multi-agent, multi-modal, multi-object goal navigation; code and data released. Promoted from the queue. [paper](https://arxiv.org/abs/2610.20121)
- **Robota-Embed** (memory): VLA embeddings for retrieval-based in-context robot learning. Promoted from the queue. [paper](https://arxiv.org/abs/2610.19495)
- **WEDGE** (sim): weakness-guided environment generation for navigation agents; partial code released. Promoted from the queue. [paper](https://arxiv.org/abs/2610.19420)
