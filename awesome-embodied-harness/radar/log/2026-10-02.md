# Radar · 2026-10-02

## Signals

- **Self-evolving harnesses are adopting software-engineering guardrails.** DynaHarness admits a capability revision only after paired regression checks. The Scale and Selection study finds that an optimizer agent rewriting a robot agent's harness degrades it unless Champion-Challenger selection gates each edit, and that rollouts per round decide whether the gains generalize. ASENA and SimEX keep weights fixed and evolve a persistent workspace or toolbox instead, with SimEX using a simulator that a few real trials correct.
- **Frontier general models as robot policies are now evaluated directly.** Galbot's study of GPT-6 Astra and LIBERO-Agent both find good task-level decisions but unreliable contact-rich and long-horizon control, at high token and latency cost. This is the gap that DynaHarness-style fast layers and MotorMind-style mid-level actions (2026-10-01) are built to fill.
- **Safety is moving from single actions to persistent policy changes, and its weak spots are showing.** FailBank turns runtime shield corrections into LoRA updates so the policy stops fighting the shield. The Multi-Link Safety Filter shields the whole arm on edge hardware. Refusals That Bend shows that one everyday object in the scene flips a fifth of refused tasks to compliance.

## Added

- **DynaHarness** (harness): a slow/fast harness with a physical execution contract and regression-gated capability revisions. [paper](https://arxiv.org/abs/2609.40306)
- **ASENA** (harness): coding agents with robot sensing, supervised execution and a persistent skill workspace; includes a 4B navigation policy, run on a Unitree G1. [paper](https://arxiv.org/abs/2609.39207)
- **SimEX** (harness): robotics autoresearch in which coding agents build a toolbox in simulation and co-correct simulator and toolbox from a few real trials. [paper](https://arxiv.org/abs/2609.38982)
- **Scale and Selection** (harness): what makes automatic harness evolution work for coding-agent robot policies. [paper](https://arxiv.org/abs/2609.39304)
- **NavHarness (adaptive goals)** (harness): Goal, Verify, Memory and Visuomotor agents for VLN. It is a different paper from the existing NavHarness entry. [paper](https://arxiv.org/abs/2609.39915)
- **FailBank** (verification): runtime safety feedback distilled into persistent VLA updates. [paper](https://arxiv.org/abs/2609.39820)
- **Refusals That Bend** (safety): one ordinary object can overturn an embodied VLM planner's refusal. [paper](https://arxiv.org/abs/2609.38971)
- **Multi-Link Safety Filter** (safety): a training-free whole-arm barrier shield around a VLA that tracks moving hazards. [paper](https://arxiv.org/abs/2609.40007)
- **GPT-6 Astra as embodied policies** (benchmark): Galbot's six-domain evaluation of a frontier model as a robot policy. [paper](https://arxiv.org/abs/2609.38537)
- **LIBERO-Agent** (benchmark): an agent-native manipulation benchmark for general-purpose agents. [paper](https://arxiv.org/abs/2609.39507)
- **RoboCoach** (world-model): imagined failures in the CoachWorld world model target demonstrations and expert updates; code and weights released. [paper](https://arxiv.org/abs/2609.39685)
- **ChronoGraph** (memory): functional 4D scene graphs for interaction understanding and grounded planning. [paper](https://arxiv.org/abs/2609.39665)
